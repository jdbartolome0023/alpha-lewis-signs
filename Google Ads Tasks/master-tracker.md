## Lessons learned (Sep 16 2026 Google Ads setup)

- **GA4 realtime only covers about 30 minutes and standard daily reports lag by hours.** A Measurement Protocol `purchase` can look missing in both for a while. Recheck the standard report 2 to 3 hours after a test order before concluding the pixel failed (Oct 6 2026: Nic's order showed up hours later, the original pixel had been working).
- **Google Ads campaign wizard review pages can show stale values** (all countries, AI Max on) after you have already fixed them. Reload, then verify in the saved draft or the campaign Settings. Ad group and ads lists can also be stale until a reload.
- **The wizard auto-creates sitelinks** (About Us, Shop All etc.) even with asset generation switched off, and it publishes the campaign Enabled, not Paused. Pause immediately after publishing and replace the auto assets with verified ones.
- **Creating ad groups one by one can carry over the display path from the previous ad** (Wall & Hanging showed `/a-frame-signs/aluminium`). Check the display paths in the Ads list after building.
- **Ad groups created this way are Paused**, so launch means enabling the campaign and every ad group (and any ad you edited), not just the campaign.
- **Status dropdown menus can open on the wrong row after a layout shift.** Select via the row checkbox and the Edit menu when removing or pausing anything.

- **Shopify custom pixels: `browser.cookie` is an object, not a function.** Use `await browser.cookie.get(name)` inside an `async` handler. Calling `browser.cookie(name)` throws silently and the pixel shows "Loaded" with 0 events (cost 4 days on Signee, fixed Oct 2 2026).
- **Test a custom pixel without an order:** (1) send a harmless named event straight to the Measurement Protocol endpoint and check GA4 Realtime to prove the property/secret, (2) temporarily add a `page_viewed` listener using the same code path, browse the site, check Realtime, then remove it the same session. Only the checkout trigger then needs a real order.
- **Google Ads UI bulk upload (Tools > Bulk actions > Uploads) needs Google's own column names and values.** Editor-style guesses failed ("EU political ads" value, negative keyword Criterion Type). Download Google's template from that page first if trying again. Always Preview, never Apply, until the preview is clean.
- **Site page URLs: test the real links from the navigation, not guessed paths.** About/FAQ looked 404 at `/pages/about-us` and `/pages/faq`, but live at `/pages/about` and `/pages/frequently-asked-questions`.
- **Google Ads account time zone and currency lock permanently at account creation and can never be changed.** If it's wrong, the only fix is discarding the account and starting over.
- The "Create your first campaign" wizard's billing-country screen is **unreliable** - it can display "Australia / Sydney Time / AUD" as if the change was accepted, but this does not always actually commit to the account. Always double check via **Admin > Account settings** directly, not the wizard.
- New account creation defaults Locations, Billing Country, and Time zone to the **MCC's own country** (Philippines, in this case) unless explicitly overridden at every step - check this at every screen, not just once.
- The wizard defaults to **Performance Max** as campaign type when the goal is "Purchases" - if Search is wanted, you must explicitly click "view other campaign types" and select Search.
- **Google Ads blocks sending user invites until the account has a payments profile** (even an incomplete/shell one) - confirmed by testing 3 different invite emails, all failing identically ("An error occurred. Please try again later.") until a payments profile existed.
- **Correction Sep 18 2026: a standalone payments profile is NOT enough on its own.** Created the Signee payments profile shell (Organization, no card) and the invite still failed with the identical error. Google's own public documentation does not confirm the exact requirement either way (checked directly, inconclusive). Working theory now: a fully completed billing setup (profile + an actual linked payment method) may be required, not just the profile record - but this is unverified, not confirmed. Do not assume adding a card will fix it without checking with Google Ads support first, to avoid another round of trial-and-error.
- Kim's email (kim@alphalewissigns.com.au) is Microsoft/Outlook-hosted, not Google Workspace - she and Nic will likely need to go through Google's "create account using my current email" flow to accept the Ads invite, not sign in directly.
- **Always check theme.liquid for existing tracking before installing anything new.** The Sep 15 audit's external page-source check found nothing, but that was before the SEO provider installed their own GA4 tag directly in theme.liquid. Confirm with all parties (SEO, dev, previous agency) whether tracking already exists before building a parallel setup.
- **Report template: never let a fixed-color background block inherit a theme-flipping text-color variable.** The weekly report's `.block.lavender` used `var(--ink)`, which flips to near-white in dark mode, against a lavender background that stays fixed light in both themes - unreadable in dark mode. Any color block with a fixed (non-theme-responsive) background must pin its own text color too, the way `.block.brown` already correctly pins to `--cream-on-brown`. Fixed Sep 25 2026 in both `week-sep-14-18-2026.html` and `period-sep-14-24-2026.html`.
